# Security Policy

## Supported versions

Security fixes are developed for the current release line. Users should run the
latest available Variable Thema release together with a supported WordPress and
PHP version.

| Version | Security support |
| --- | --- |
| 1.x | Supported |
| Earlier versions | Not supported |

## Reporting a vulnerability

Do not report a suspected vulnerability in a public GitHub issue, discussion,
pull request, or social media post.

While this repository is private, contact the repository maintainers directly.
Before the repository becomes public, GitHub Private Vulnerability Reporting or
another private reporting channel will be configured and this section will be
updated with the exact route.

Include only the information needed to investigate:

- Affected version and environment.
- Reproduction steps or a minimal proof of concept.
- Expected and observed behavior.
- Potential impact.
- Any known mitigation.

Do not include production credentials, API keys, customer data, or unnecessary
personal information. If sensitive supporting material is required, wait for a
maintainer to provide an appropriate private transfer method.

## Response expectations

Maintainers will acknowledge reports when practicable, investigate their scope,
and coordinate a fix and disclosure plan when warranted. No specific response
or remediation deadline is guaranteed.

Please allow maintainers reasonable time to investigate and release a fix
before public disclosure.

## Scope

This policy covers security issues in Variable Thema. Vulnerabilities in
WordPress Core, a Skin, a plugin, hosting, or a site-specific integration should
be reported to the appropriate project or operator.
